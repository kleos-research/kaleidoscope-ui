Kaleidoscope — redesign directions
Three flows, two directions each. Pick per flow — they don't have to agree.
Same colours as the app you saw, on purpose: the only thing changing here is structure, so nothing you react to is a palette change in disguise. The one visual addition is a serif for memory prose — a memory is a document, and it should read like one.
The diagnosis
“No thinking balance. I wanted to have these functions, so I just put everything together at one place.”
That is exactly right, and it names the cause. Every screen was built to never mislead — every count, caveat and “here is what this can’t show” resident at once. Being honest about a thing and showing all of it simultaneously are not the same requirement. Nothing below deletes a capability; everything is moved, deferred, or renamed.
1  Browse
the list
The problem
You open this because you suspect the agent knows something wrong — or you just want to see what has piled up. You need to move through a few hundred memories and notice the ones that look off. Today three always-open filter columns, a five-column table and two lines of hint text all compete, so there is no obvious place to start looking.
A — One list
No rail. Filters are added from one control, and read back as removable chips. Rows are quiet and generous.
B — List and preview
Compact list on the left, the selected memory on the right. Faster to triage many; you read without losing your place.
2  Read
one memory
The problem
You clicked a title to judge whether this memory is right. What you need is the sentence it asserts and the facts your agent will actually act on. Today the first thing on screen is a block of field names — Applies to, Written, Version, Memory — and the facts sit a long scroll below the prose.
A — Document
One column. Title, prose, then what it asserts. Everything else is a labelled row with a count, closed until you want it.
B — Prose with a rail
Facts pinned beside the prose, never scrolled away — so you can see the words and what they became at the same time.
3  Fix
the editor
The problem
Nearly every edit is a wording fix; occasionally a fact is wrong. But a save replaces the words and the structure together, so if the facts are hidden the two drift apart silently. Today both columns are full, the first thing on screen is a paragraph of field names, and there is no obvious first move.
A — Write, with a shelf
The page is the words. Facts sit on a shelf along the bottom, always readable, opening when you touch them.
B — Two panes, two things
Keeps side-by-side, but each side holds exactly one thing. Everything else moves behind a single Details button.
Two things I changed everywhere, without being asked
Project moved to the top bar. You were right that everything sits under a project. It is a switcher now, not a filter facet — with an all-projects view, and “applies everywhere” treated as its own thing rather than a project called none.
Branch and file left the default surface. You didn’t know what they did, which is the answer. They are still filterable and still shown on a memory that has them — they are just no longer three columns of chrome you have to scroll past.
Not drawn yet: removal, the curation backlog and the graph. They all inherit whatever shell and density you pick here, so drawing them first would be guessing twice.
